# 桌面宠物（Windows + macOS）可行性分析与技术选型

> 状态：讨论定案（M0 验证前基线）。日期：2025-08。
> 定位：开源 / 个人使用。支撑 Windows 与 macOS 同步开发。
> 核心诉求：非像素风格桌宠；可被 agent（codex 等）通过 MCP / CLI / Hooks 控制；
> 内置管理配置界面；支持导入自定义形象与动作；把「从零生成宠物」做成可视化界面。

---

## 1. 决策记录（已拍板）

| 决策项 | 结论 | 理由 |
|---|---|---|
| 壳层 | **Tauri v2（Rust + React/TS）** | 体积小、性能好；三个跨平台先例（Kotori Pet / CodexPetDesk / convai-desktop-pet）证明路线通 |
| 动画质感 | **手绘/高清序列帧**（非像素风） | 质感上限来自母版分辨率与素材质量，而非格式；跨平台 100% 兼容；避开 Live2D 许可与 WebGL 兼容坑 |
| 平台 | **Windows + macOS 同步开发** | 从第一天按跨平台设计，macOS 的坑尽早暴露，避免后期移植返工 |
| 商业化 | 开源 / 个人使用 | 无许可负担，技术选型自由度最大；资产格式保持可替换性 |

### 1.1 动画方案对比依据（序列帧 vs Live2D，2025-08 复核）

评估维度权重：平台兼容性 > 效果与 AI 生成便利性 > 实现复杂性。

| 维度 | 序列帧 spritesheet | Live2D |
|---|---|---|
| 平台兼容 | ✅ canvas 2D + WebP/PNG 帧，Chromium/WKWebView 100% 一致 | ⚠️ WebGL 渲染理论可用，但无 macOS 桌宠生产验证；纹理扩展有模型相关兼容风险，需 M0 实测 |
| 生态维护 | ✅ PIXI 官方持续维护（v8 现役） | ⚠️ pixi-live2d-display 停更于 0.4.0（2023-12），peerDep 锁 PIXI v7，需第三方 patch |
| 效果上限 | 静态观感取决于母版分辨率（参考 2160×1215）；动态交互弱（预设帧序列） | 动态交互碾压级：口型同步/表情参数/视线跟随/物理摆动 |
| **AI 生成自定义形象** | ✅ 全自动管线已验证：提示词 → 视频生成 → HSV 抠像 → 归一化 → 转帧；动作模板现成（MIT） | ❌ 官方 Cubism 格式无法 AI 生成（拆件/绑骨/动作全手工）；替代方案 AutoLive2d 是自研格式，不可导入 Cubism 模型 |
| 实现复杂性 | 低（AnimatedSprite + 图集/帧表 JSON） | 中高（PIXI 版本锁定、Cubism Core WASM、模型管理、映射层） |
| 结论 | **选型确定** | 动态交互优势通过「机制帧」（嘴型/眨眼/情绪帧按文本节奏切换）在序列帧侧弥补 |

设计约束（由此决策衍生）：
- 渲染层做后端抽象：宠物 Actor 接口（play / say / setEmotion），序列帧实现先行，Live2D 作为可插拔后端保留。
- 参考 [AutoLive2d](https://github.com/Fenglin-Maple/AutoLive2d)（Apache-2.0）：其「单图 → AI 拆层 → 自动绑骨 → 可视化编辑 → 导出包」流程作为生成向导的交互参照，拆层/绑骨算法思路可借鉴。

### 1.2 素材复用与转帧验证（2025-08 实测）

第一阶段目标：**复用 [dsh-pet-standalone](https://github.com/ianlike-ui/dsh-pet-standalone) 的 51 段素材（MIT）**，做功能对齐的双平台桌宠（多桌宠 / 动画链 / 点击拖拽 / 右键菜单 / 托盘 / 自启 / 4 档缩放 / 配置持久化）。

**实测结论：转帧不能依赖 ffmpeg 命令行**：

| 验证项 | 结果 |
|---|---|
| 素材规格 | 51 段 640×360 VP9 webm，24fps，10s/段（约 241 帧），35MB，源自 MIT 的 dsh-pet（需在 README 声明出处） |
| webm 结构 | 主色流 `yuv420p` + BlockAdditional 藏 alpha（EBML 251 个 BlockAdditions，流标签 `ALPHA_MODE: 1`） |
| ffmpeg 转 PNG | 输出 color_type=2 **无 alpha**，透明区域变纯黑（像素实测 `000000`）——ffmpeg 丢弃 VP9-alpha 非标准扩展数据 |
| 体积量级 | 无损 PNG 24fps ≈ 1GB / 12fps ≈ 560MB；WebP 无损 12fps ≈ 365MB；WebP 有损 q80 12fps ≈ 225MB（原始 35MB，帧间压缩丢失） |

**转帧可行路径（二选一）**：
- **方案 A（首选）**：复用 standalone 的 `webm.rs + vpx.rs + clip.rs`（MIT、平台无关）做离线转帧工具（Rust CLI），直接取出官方已抠好的 alpha，输出 WebP 图集；macOS 侧 libvpx 源码编译。
- **方案 B（备选）**：从原版 dsh-pet GitHub Releases 取绿幕源 mp4，复用其 HSV 抠像脚本重新抠像出 RGBA 帧。

**实现状态：方案 A 已完成并验证（2025-08）**：

- 工具位置：`tools/webm2frames/`（Rust，`webm2frames` + `decode_check` 两个 bin）。
- 适配：`vpx.rs` 的 `#[link(name = "vpx")]` 链接 Homebrew libvpx（`build.rs` 里 `cargo:rustc-link-search` 定位 brew prefix/lib）；`clip.rs` 输出 premultiplied BGRA → 工具内转回 straight-alpha RGBA。
- 实测结果（macOS Intel，release 构建）：
  - `decode_check`：241 帧全部带 alpha（对比 ffmpeg 0 帧）；alpha 分布 83% 透明 / 16.6% 不透明；解码 2.6ms/帧。
  - `webm2frames`：输出帧像素验证——角落 alpha≈0（透明）、人物主体 alpha=255（不透明），边缘干净无黑边（视觉确认）；耗时约 7ms/帧。
  - 体积实测：**无损 WebP 12fps ≈ 8MB/动画（51 个 ≈ 427MB / 6171 帧）**；无损 PNG 24fps ≈ 26MB/动画（51 个 ≈ 1.3GB，不可行）。image crate 的 WebP 编码器仅支持无损；有损编码需换 `webp`/`libwebp-sys` crate（待办）。
- 下一步：批量转换全部 51 段素材（已完成，产物 `assets/frames/` + `meta.json`）；有损 WebP 支持；图集打包（TexturePacker 格式）。

**体积缓解**：抽帧 12fps + WebP 有损 + 按需懒加载（idle/常用动作常驻，其余用时加载）+ 素材包外置下载；远期可做 Windows 运行时直接解 webm 的加速路径。

**架构约束**：功能对齐 standalone，但技术路线维持 Tauri + PIXI（一套代码双平台）；standalone 的 `app.rs / state.rs / config.rs`（MIT）作为行为逻辑移植蓝本。

## 3. 收敛后的目标架构

```
┌─ agent 侧 ─────────────────────────────────────────────┐
│  Codex / Claude Code / OpenCode                        │
│    ├─ Hooks 协议（自动事件：SessionStart/Stop…）        │
│    └─ MCP client（mcpServers 配置，主动调用工具）        │
└────────────────────────────────────────────────────────┘
                    │
┌─ 控制层（Rust，独立于渲染进程）───────────────────────────┐
│  MCP server（stdio，独立可唤醒）   CLI（pet …）            │
│  Hooks 脚本（codex/claude/opencode 事件 → 指令）          │
│                  ↓ 统一指令协议（JSON over socket）        │
│          本地端点：Unix socket（macOS）/ 命名管道（Windows）│
└────────────────────────────────────────────────────────┘
                    │ IPC（Tauri command / event）
┌─ 渲染层（Tauri v2 + React + PIXI.js canvas）────────────┐
│  dashboard 窗口（普通窗口）：角色管理 / 设置 / 导入 / 生成向导 │
│  overlay 窗口（透明·置顶·穿透）：PIXI 场景图 + 行为状态机     │
│    渲染：高清序列帧 spritesheet（帧表 JSON + 图集）          │
│    多宠物支持，每只独立动画链 / 位置 / 朝向 / 缩放            │
└────────────────────────────────────────────────────────┘
```

### 关键设计决策

1. **渲染层用 PIXI.js（canvas/WebGL 场景图）**，React 只做 UI 壳。原因：
   - `AnimatedSprite` 原生支持 spritesheet 帧动画，多宠物、缩放、镜像、混合、alpha 命中检测都方便；
   - 与 Live2D 无关，避开 WKWebView WebGL 兼容风险面；
   - 序列帧在 Chromium / WKWebView 下 100% 一致（canvas 2D 兜底）。
2. **动画资产走「图集 + 帧表」而非透明视频**：macOS WKWebView 不支持视频 alpha 通道（VP9+alpha webm 在 Windows 可行、macOS 不可行），这是从 dsh-pet 移植的最大坑，**转帧序列彻底规避**。
3. **非像素质感来自母版分辨率 + 素材管线，而非格式**：原版母版 2160×1215、播放 640×360；本方案播放目标 ≥720p，图集内帧按需缩放，保证观感。
4. **控制层独立于渲染进程**：MCP server 以独立可执行/独立进程方式提供，桌宠未运行时 agent 调用可唤醒主程序（single-instance 插件处理）。

## 4. 宠物包格式规范（草案，开源项目的核心契约）

对齐 Hatch-Pet 的「目录即宠物」思想，但支持高清序列帧与动作语义：

```
pet-name/
├── pet.json          # manifest：id / displayName / description / 脚底锚点 / 默认尺寸
├── atlas/            # 图集（每动作一张或共享大图）
│   ├── idle.png      # + 帧表 JSON（x/y/w/h/duration/name）
│   ├── wave.png
│   └── …
└── behaviors.json    # 动作→状态映射：idle / turn / act[] / move / respond
                      # 每动作：概率权重、循环性、朝向镜像、落地对齐、触发指令名
```

- 兼容层：接受 Hatch-Pet 包（`pet.json + spritesheet.webp`）与 dsh-pet 素材链产物（自动转帧）作为导入源。
- 行为状态机沿用原版概率链模型（30% 待机 / 10% 转向 / 40% 动作 / 20% 移动），外部指令（MCP/CLI/Hooks）以更高优先级插入。

## 5. 控制层三通道

| 通道 | 触发方式 | 实现 | 用途 |
|---|---|---|---|
| **Hooks** | agent 生命周期事件自动触发（codex: SessionStart/Stop；claude: Stop/PreToolUse；opencode: 插件） | 配置脚本 → 组装 JSON 指令 → socket 推送 | 任务完成自动反馈（庆祝/叹气/播报），零 agent 改动 |
| **MCP** | agent 主动调用工具 | MCP server 暴露 `pet.play / pet.say / pet.set_state / pet.get_state / pet.spawn / pet.dismiss` | codex 等在任务中主动控制桌宠 |
| **CLI** | 任意脚本/终端 | `pet say "…"` / `pet play dance`，薄封装同一端点 | 最低门槛通道，cron / shell / 其他 agent |

协议：统一 JSON 指令（`{op, petId?, args, seq}`），本地端点 Unix socket（macOS）/ 命名管道（Windows），Tauri Rust 侧持有。

## 6. 素材生成管线（可视化生成向导的引擎）

复用 [dsh-pet 的 MIT 管线](https://github.com/PC2005-cloud/dsh-pet/blob/master/DESIGN.md)：

```
AI 提示词（角色描述 + 动作分解）
  → 视频生成 API（豆包/即梦/可灵 等，绿幕 16:9）
  → ffmpeg HSV 色相抠像（绿相 70~170° 且 饱和度/明度≥0.15 → 透明）
  → 归一化（统一画布、非透明像素 x 中位数居中、脚底锚点）
  → 转帧序列 → 图集打包（+帧表 JSON）
```

可视化向导（dashboard 内）：**描述角色 → 选风格模板 → 调参数 → 逐动作生成/预览 → 打包为宠物包**。
原版 51 段动作提示词模板（待机/打瞌睡/玩魔方/炸毛/吐泡泡…）可直接作为模板库起点。

## 7. 穿透与交互方案

- 透明窗口：Tauri `transparent + decorations:false + alwaysOnTop`。
- 点击穿透：`set_ignore_cursor_events(true)`（Win/mac 均可用，参考 [tauri #10564](https://github.com/tauri-apps/tauri/issues/10564)）。
- 交互区：前端按 alpha 蒙版 + 气泡/UI 区域计算 hit-region，Rust 侧 60Hz 光标轮询按需切换穿透（Kotori Pet / convai-desktop-pet 已验证模式）；拖拽期间保持捕获，防「穿透态轮询链断裂卡死」类问题（Kotori Pet bugfix 有现成教训）。
- DPI/多显示器：跨 IPC 一律物理像素，渲染层统一除 scale（convai-desktop-pet 约定）。
