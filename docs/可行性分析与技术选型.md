> **当前状态（做了什么）**、**后续路线（要做什么）**。配套文档：[需求规格](需求规格.md)。

---

## 1. 技术选型与理由

### 1.1 历史（简要）

- 曾选 **Tauri v2 + React/PIXI 序列帧**（M0 原型验证通过）→ **弃用**：
  VP9+alpha webm 无法用 ffmpeg 转帧（alpha 丢失）需自研工具、序列帧膨胀（≈430MB）、
  壳层 + 前端渲染带来运行时依赖与体积开销。
- 现行为**纯原生**：Windows Win32 / macOS AppKit。

### 1.2 现行决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 壳层 | 纯原生 Win32 / AppKit | 单文件自包含、零运行时依赖、启动快、性能上限高 |
| 渲染 | libvpx 静态链接直接解码 webm，逐像素合成（`UpdateLayeredWindow` / `CGBitmapContext`）| 素材即用不转帧；alpha 存于 BlockAdditional 扩展（ffmpeg 会丢），必须 libvpx 层 API 读取 |
| 平台 | Windows + macOS 同步 | 平台中立核心 + 双后端，行为一致 |
| 素材 | 运行时目录加载、不内嵌；**发布物仅二进制**，素材经控制台导入 | 可替换可导入；exe 瘦身；贴合「配置可自定义」方向 |
| 控制层 | **单一本地 HTTP 服务**（127.0.0.1）；不提供 CLI / MCP / Hooks | 一通道覆盖控制 + 前端托管；协议简单，Agent/脚本直接调 API |
| 管理界面 | **浏览器控制台**，前端编译期内嵌二进制（`include_bytes!` / `rust-embed` / `include_dir`）| 跨平台一致、前端生态成熟；保持单文件分发 |
| 数据 | **单 config.json**（用户偏好）+ **SQLite**（程序数据，rusqlite）| 偏好可手改热生效；结构化数据（素材索引/聊天记录）入库 |
| 桌宠模型 | 单只桌宠（裁剪多角色/多桌宠）| 聚焦核心体验，控制复杂度 |
| 许可 | MIT（本项目）+ 上游素材 MIT 声明 | 无许可负担，保留可替换性 |

## 2. 技术要点（现状实现）

- **渲染**：Windows `UpdateLayeredWindow`（BGRA premultiplied，AC_SRC_ALPHA）；
  macOS 无边框透明 NSWindow + NSView 逐帧 drawRect → CGBitmapContext → CGImage；
  缩放/镜像共享 `gfx::scale_bgra`（4 档：50%/72%/85%/100%）。
- **穿透与交互**：Windows `WM_NCHITTEST`（像素 alpha<128 → HTTRANSPARENT）+ `WM_SETCURSOR`
  手型；macOS `ignoresMouseEvents` 按光标位置逐 tick 切换（窗口服务器层真穿透；
  代价：光标样式失效，悬停手型仅 Windows）。
- **菜单/托盘/自启/配置**：数据驱动 `MenuEntry`；托盘右键完整菜单（P4 起含「打开控制台」）；
  Windows `Shell_NotifyIconW` / macOS `NSStatusItem`；自启注册表 / LaunchAgent；
  单文件 `config.json`（rx/ry 归一化；首次运行自动从旧版 Tauri 配置迁移）。
- **构建**：build.rs 探测静态 libvpx（`VPX_LIB_DIR` > vcpkg > brew；
  macOS 传 `.a` 绝对路径强制静态，避免 ld 优先 dylib）；
  `opt-level=z + lto + strip`；打包脚本 `tools/pack.ps1` / `pack.sh`。
- **本地 HTTP 服务（P4 规划）**：tiny_http 内嵌线程；默认端口 18686、冲突回退随机、
  端口写 `control.json`；静态托管内嵌前端 + `/api/*`；仅绑 loopback + Host/Origin 校验。

## 5. 路线图（后续要做什么）

### P3 —— 行为策略 + 工程化

- `behavior` 配置块（calm/balanced/lively 预设 + weights/move/scale_steps），
  `state.rs` 常量改为策略参数（默认值 = 现常量）；
- 单元测试：动画链状态机、配置读写与迁移、菜单数据、`gfx::scale_bgra` 边界；
- CI 暂缓；素材获取流程文档化。

### P4 —— 控制层 + 基础控制台（核心里程碑）

- 内嵌 HTTP 服务（`tiny_http`）：绑定 127.0.0.1，默认 18686（可配），冲突回退随机，
  实际端口写 `control.json`；
- JSON API：`state / config（GET+PATCH 热生效）/ pet.say / pet.play / pet.move /
  pet.set_state / quit`；
- 托盘「打开控制台」→ 默认浏览器打开管理界面；
- 前端工程 `web/`（Vite + React + TS）：状态面板 + 指令面板 + 配置表单
  （缩放/置顶/不移动/行为策略（依赖 P3）/角色切换）；产物编译期内嵌 + 占位页兜底；
- 桌宠侧：指令队列（外部指令高优先级插入动画链）；`say` 气泡平台层绘制；
- 导入基础：目录 / zip → 校验 → 预览 → 注册（SQLite）→ 切换角色；
- 调试面板：调用并查看对外 HTTP API；
- SQLite（rusqlite）：素材索引 / 导入记录 / 聊天记录；
- 单配置整理：全部用户偏好收敛到一个 `config.json`；
- 发布物调整：打包脚本不再包含素材，zip = 二进制（素材包独立提供，经控制台导入）；
- 安全：仅绑 127.0.0.1 + `Host`/`Origin` 校验。

### P5 —— 控制台完整化

- 导入策略打磨（来源 / 流程 / 失败处理完善）；素材包独立发布机制；
- 聊天面板与对话能力（本地规则优先，Agent 接入可选）；
- AI 生成素材（描述 → 视频生成 → HSV 抠像 → 归一化 → 打包为新角色）。
