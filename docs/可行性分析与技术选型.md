# deskpet 桌宠 —— 技术选型、现状与路线图

> 状态：**现行**（2025 重写）。本文档替代早期 Tauri 方案文档，反映已拍板的原生实现路线。
> 定位：开源 / 个人使用。Windows + macOS 双平台。
> 配套文档：[需求规格](需求规格.md)（发展需求的细节定义，本路线图的分期依据）。

---

## 1. 决策记录

### 1.1 历史决策（已弃用）

早期选型曾拍板 **Tauri v2 + React/PIXI 序列帧** 方案并完成 M0 原型验证（透明窗口、
WebP 帧动画、点击切换均实测通过）。该方案因以下原因**整体弃用**：

- 转帧链路复杂：VP9+alpha webm 无法用 ffmpeg 转帧（alpha 丢失），需自研离线转帧工具；
- 序列帧体积膨胀（无损 WebP ≈ 430MB），依赖素材外置与懒加载；
- Tauri 壳层 + 前端渲染带来运行时依赖与体积开销；
- 素材格式与渲染链路过长，维护成本高。

### 1.2 现行决策（原生方案，A 方案）

| 决策项 | 结论 | 理由 |
|---|---|---|
| 壳层 | **纯原生**：Windows Win32 / macOS AppKit | 单 exe（~36MB）自包含、零运行时依赖、启动快、性能上限高 |
| 渲染 | **libvpx 静态链接直接解码 webm**，逐像素合成 | 51 段 VP9+alpha webm 无需转帧，素材即用；`UpdateLayeredWindow` / `CGBitmapContext` 原生合成 |
| 平台 | Windows + macOS 同步 | 平台中立核心 + 双后端，行为一致 |
| 桌宠模型 | **单只桌宠**，裁剪多角色/多桌宠/右键"播放任意动画" | 聚焦核心体验，控制复杂度 |
| 许可 | MIT（本项目）+ 上游素材 MIT 声明 | 无许可负担，保留可替换性 |
| 功能集 | 待机/转向/移动/点击回应/拖拽/置顶/不移动/自启/4 档大小/回到右下角/托盘 | 对齐上游 standalone 并保留既有能力 |

### 1.3 素材复用（2025 实测）

- 51 段 640×360 VP9+alpha 透明 webm（24fps，10s/段，合计约 35MB），源自
  [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)（MIT）动画链行为模型；
- 取自 [ianlike-ui/dsh-pet-standalone](https://github.com/ianlike-ui/dsh-pet-standalone)（MIT）；
- alpha 藏在 BlockAdditional 扩展（EBML BlockAdditions，`ALPHA_MODE: 1`），ffmpeg 会丢弃，
  必须用 libvpx 层 API 读取——原生方案直接复用 standalone 的 `webm.rs / vpx.rs / clip.rs`（MIT）解码；
- 素材不入库（体积考虑），从上游仓库复制 `assets/videos/*.webm` 到本地。

## 2. 技术选型（原生方案）

### 2.1 渲染

- Windows：`CreateWindowExW`（`WS_EX_LAYERED|TOOLWINDOW|NOACTIVATE[|TOPMOST]`）+
  `UpdateLayeredWindow`（ULW_ALPHA，BGRA premultiplied，`AC_SRC_ALPHA`）；
- macOS：`NSWindow` 无边框透明（`NSFloatingWindowLevel` 置顶）+ 自定义 `NSView` 逐帧
  `drawRect` → `CGBitmapContext`（BGRA premultiplied）→ `CGImage`；
- 缩放/镜像由共享 `gfx::scale_bgra` 完成（4 档：50%/72%/85%/100%）。

### 2.2 穿透与交互

- 穿透：Windows `WM_NCHITTEST` 按像素 alpha<128 → `HTTRANSPARENT`；macOS 窗口级
  `ignoresMouseEvents` 按光标位置逐 tick 切换（窗口服务器层真穿透）；
- 点击回应：待机时点击随机播放回应动画；
- 拖拽：Windows `SetCapture` / macOS AppKit 按下期间隐式捕获 + 全局坐标跟手；
- 悬停：光标在桌宠身上（不透明像素）→ 手型提示（Windows `WM_SETCURSOR`）。

### 2.3 菜单 / 托盘 / 自启 / 配置

- 菜单：数据驱动 `MenuEntry`（`menu.rs`），两平台渲染成原生菜单；**完整菜单在托盘右键**
  （回到右下角/置顶/不移动/自启/大小/显示隐藏/退出），桌宠身上不弹菜单；
- 托盘：Windows `Shell_NotifyIconW`；macOS `NSStatusItem`；左键单击切换显示/隐藏；
- 自启：Windows `HKCU\...\Run`（值名 `deskpet`）；macOS `~/Library/LaunchAgents/com.kiry.deskpet.plist`；
- 配置：Windows `%APPDATA%\deskpet\config.json` / macOS `~/Library/Application Support/deskpet/config.json`；
  位置用归一化 `rx/ry`（0..1，主屏工作区）；首次运行自动从旧版 Tauri 配置迁移；
  `autostart` 不持久化在配置中（以系统启动项管理为准）。

### 2.4 构建

- `build.rs`：素材打包 `assets.pak` + 生成索引；libvpx 探测
  （`VPX_LIB_DIR` > `VCPKG_ROOT/installed/*/lib` > 平台约定路径；macOS 另探测 brew）；
- Windows：vcpkg `libvpx:x64-windows` 静态链接；`opt-level=z + lto + strip`，单 exe ~36MB；
- macOS：`brew install libvpx`；跨平台类型检查
  `DESKPET_ALLOW_NO_LIBVPX=1 cargo check --target aarch64-apple-darwin`。

## 4. 已知缺口

| 缺口 | 说明 |
|---|---|
| 单实例锁 | 重复启动会开多个桌宠（需 CreateMutex / flock）|
| exe 图标 | 无嵌入图标资源（仅有运行时生成的托盘图标）|
| 分发 | 只有裸 exe，无 zip/安装包 |
| 测试 | 无单元测试（仅 `decode_check` 素材校验）|
| CI | 无（已决策暂缓）|

## 5. 路线图

### P1 —— macOS 真机验证（需 Mac，最高优先）

- [ ] 真机构建链（rustup target + brew libvpx + `cargo build --release`）
- [ ] 验证 §3.2 五项待确认项并修复发现的问题
- [ ] 双击/拖拽/点击回应/托盘全流程回归

### P2 —— 素材分离 + Windows 打磨（需求规格 §1、§2）—— ✅ 完成

- [x] **素材分离**：运行时从目录加载（不再内嵌 pak）；配置 `assets_dir`/`character`；
      素材 manifest 规范落地（`docs/需求规格.md §1.4`）；exe 由 37.9MB 瘦身至 1.5MB
- [x] zip 打包：`tools/pack.ps1` → `deskpet-v<版本>-windows-x64.zip`（exe + 素材 + README/LICENSE）
- [x] 单实例锁（`File::try_lock`，配置目录锁文件；重复启动直接退出）
- [x] exe 图标（`resources/deskpet.ico` + `embed-resource` 嵌入；托盘图标仍运行时生成）

### P3 —— 行为策略 + 工程化（需求规格 §5）

- [ ] 行为策略配置化：`behavior` 配置块（calm/balanced/lively 预设 + 权重/移动参数覆盖）；
      `state.rs` 常量改为策略参数（默认值 = 现常量）
- [ ] 单元测试：动画链状态机（概率链/移动规划）、配置读写与迁移、
      菜单数据、`gfx::scale_bgra` 边界
- [ ] CI 暂缓（已决策）；素材获取流程文档化

### P4 —— 控制层（需求规格 §4，已决策列入）

- [ ] 本地端点：Windows 命名管道 / macOS Unix socket（Rust 实现，单实例进程内）
- [ ] 指令协议：`say / play / move / set_state / get_state / quit`（JSON，`{op, args, seq}`）
- [ ] CLI：`deskpet say "…"` / `deskpet play <action>` / `deskpet move <x,y>`（配合单实例唤醒）
- [ ] MCP server（stdio）：`pet.say / pet.play / pet.move / pet.set_state / pet.get_state`
- [ ] Hooks 脚本：codex / claude / opencode 事件 → JSON 指令推送
- [ ] 桌宠侧：指令队列，外部指令高优先级插入动画链状态机

### P5 —— 配置界面（后期，需求规格 §6、§7）

- [ ] 配置界面（原生窗口）：素材管理（选择/导入/预览/校验）、行为策略、外观、位置；
      修改热生效
- [ ] 自定义素材导入向导
- [ ] AI 生成素材（描述 → 视频生成 → HSV 抠像 → 归一化 → 打包为新角色）
