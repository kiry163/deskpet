# deskpet 行为状态机设计（V3 定稿 · 引擎分层版）

> 状态：**V3 方向（2025-12 收敛，架构级定稿）**。本件把「桌宠自主动作」设计成**独立状态机引擎 + 行为层**：
> 状态机只产出「当前状态」（纯函数），行为层读状态播动作、并被**交互/外部能力**打断而不改状态。
> 语义层**抹除「素材集/素材」**，统一**宠物（pet）+ 动作（action）**。
> 配套：[需求规格](需求规格.md)、[素材转换与集成方案](素材转换与集成方案.md)、
> [可行性分析与技术选型](可行性分析与技术选型.md)。

---

## 1. 语义概念重构

| 概念 | 定义 | 关系 |
|---|---|---|
| **宠物（pet）** | 一个可切换的桌宠角色；桌面始终只显示一只 | 宠物 = 一套动作的**容器** |
| **动作（action）** | 一段可播放的动画（VP9-alpha webm）；一次导入/转换的最小单位 | 动作 ·——< 宠物（一个动作只属于一只宠物）|

- **无独立「素材库/素材集」层**。
- 交互触发**只保留两类**：`click`、`drag`，**仅交互时触发**。
- 其余（旧 `idle / turn / move / acts`）**全部并入状态池**，不再单独管理这些"触发语义"。
- 宠物在**导入时命名**（`display_name`），展示一律用该名称。

## 2. 整体分层：状态机引擎与行为层解耦

把「决策」与「执行」彻底分开，形成三层（优先级从低到高叠加）：

```
┌────────────────────────────────────────────────────┐
│ 能力层（外部 Agent / 程序）                         │
│   play(动作) / say(说话) / move(位置)…              │
│   由外部调用；**最高优先级**；可被新指令替换；          │
│   **不改变 current_state**                          │
└───────────────▲────────────────────────────────────┘
                │ 打断/覆盖（有外部指令时）
┌───────────────┴────────────────────────────────────┐
│ 交互层（用户）                                      │
│   click / drag → 即时回应                           │
│   短暂打断；**不改变 current_state**                 │
└───────────────▲────────────────────────────────────┘
                │ 打断（有用户交互时）
┌───────────────┴────────────────────────────────────┐
│ 状态内动作层（默认行为）                            │
│   读 current_state → 该状态动作池 → 加权随机 → 播放   │
│   → 间隔 → 循环                                     │
└───────────────▲────────────────────────────────────┘
                │ 读取 current_state
┌───────────────┴────────────────────────────────────┐
│ 状态机引擎（StateMachineEngine）                    │
│   输入：时钟 + 状态集合配置                          │
│   输出：current_state（纯函数，内部维护，不对外设置）  │
└────────────────────────────────────────────────────┘
```

- **状态机引擎**：纯逻辑，只算"当前状态"，**内部维护**；不把"状态切换"暴露给外部（仅暴露**只读** `current_state` 供展示/Agent 只读）。
- **行为层**：读 `current_state` 播状态池；当被交互或外部能力打断时执行别的，**期间状态不变**。
- 一次性任务 / 外部调用后，**状态不需要改变**——变的只是"在播什么"。

### 2.1 能力层（外部 Agent）语义

- `play(action)`：强制播放一个动作（一次性/可替换）。
- `say(text)`：说话气泡（一次性）。
- `move(...)`：移动 / 改变位置。
- **优先级最高**：存在能力指令时覆盖状态内动作；执行完/被替换后回到当前状态的自主循环。
- **不改变 current_state**：状态机仍按自己的调度走。

## 3. 状态（State / 阶段）

### 3.1 状态集合（程序级、用户可编辑）

- 内置 `idle`（待命）/ `active`（活跃）；**默认额外预置 `lunch`（午休）**；用户可自定义新增（如其他）。
- **控制权交给用户**：状态集合作为可编辑列表，用户可增删/改名/调参/启停；
  少数**特殊类型**是否禁改（如某些系统保留类型）**先不做特殊处理，后续再看**——简单起见，暂允许全部编辑。
  默认值见 §10.1。

### 3.2 每个状态的配置：时间规则 + 权重（同级、均可调）

| 字段 | 说明 |
|---|---|
| `weight` | 参与**加权随机**的权重；`0` = 不参与随机（仅由时间规则进入）|
| `time_rules[]` | 可选固定时段规则列表，命中即**强制**进入；支持多种规则（进入/结束时机可配）|
| `interval_ms` | **动作间隔**（状态级，非动作级）：在该状态下播完一个动作后、等多久再播下一个（如 idle 5~10s、active 2~3s）；可给范围（min~max 随机），缺省取程序级默认 |

### 3.3 时间规则的进入/结束时机

每个时间规则可配进入、结束语义（**默认准点**）：

```json
{ "start":"12:30", "end":"14:00",
  "enter":"instant",   // instant=到点直接进入 | next_window=顺延到下一个窗口边界
  "exit":"at_end" }    // at_end=到点即结束   | next_window=顺延到下一个窗口边界
```

- `enter: instant`：到 `start` 时刻**立即**进入（默认）。
- `enter: next_window`：到 `start` 后，**等到下一个窗口边界**才进入（如 12:30 设在 12:30，但等到 13:00 窗口才切）。
- `exit: at_end`：到 `end` 时刻**立即**退出（默认）。
- `exit: next_window`：过 `end` 后**顺延到下一个窗口边界**才退出。

> 进入/结束时机**按状态（时间规则）配置**，而不是全局定死——由"准点 vs 顺延"这一取舍下放给每个状态自己选。

### 3.4 调度决策（纯函数，按权重、无优先级）

```
当前时刻 t：
  命中集合 H = [ s ∈ states | s.enabled 且 ∃ 规则 r 覆盖 t ]
  ├─ H 非空：按 weight 加权随机，从 H 中选一个（多个时间规则同时段命中 → 也按权重，无优先级）
  └─ H 为空（自由时段）：按 weight 加权随机，从「weight>0 且 enabled」的状态中选一个
```

- **不做优先级区分，一律按权重裁决**（用户已确认：同一时段多个任务、自由时段均按权重随机）。
- 窗口粒度：`window_minutes`（默认 60）用于**权重随机的刷新**——在每个窗口边界重新摇一次；
  时间规则的 `enter/exit` 按各自语义在**分钟**级生效（instant 准点 / next_window 顺延到窗口边界）。

### 3.5 状态内的动作循环（行为层默认行为）

1. 候选 = 该状态动作池中被启用（enabled）的动作；
2. 按 `weight` 加权随机选一个播放；
3. 播完按**当前状态的 `interval_ms`** 停顿（**间隔属于状态，非动作**）；
4. 循环；期间被交互或外部能力打断则执行别的，播完回到当前状态的自主循环。

## 4. 配置分层

| 层 | 载体 | 内容 | 说明 |
|---|---|---|---|
| **程序级** | SQLite `app_settings`（`behavior` 段，JSON）| **状态集合**（idle/active/自定义，各自 weight + time_rules + interval_ms + enabled）、`window_minutes`、移动参数、缩放档、**转换默认参数**、任务并发 | 全局节奏；**用户可在设置页编辑状态集合**（含每状态的动作间隔）|
| **宠物级** | SQLite `pets` + `pet_actions` | 动作归属（`interactive` or `state_id`）、状态池内每动作 weight/enabled、**全身照 full_body_image**、显示名 `display_name` | 按宠物隔离（**不含间隔**，间隔在程序级状态上）|
| **系统级** | `deskpet.yaml` | `database_path / assets_dir / console_port / log_level` | 仅引导 |

- **宠物级覆盖：本轮不做、不预留冗余设计**。状态集合与调度只做**程序级全局**；后续确有必要再评估。
  （不设 `state_overrides`，避免首期冗余。）

## 5. 宠物级动作归属模型（多状态，按状态各自概率）

```sql
CREATE TABLE pet_actions (         -- 动作注册表
  pet_id      TEXT NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  action      TEXT NOT NULL,       -- 动作 key = webm 文件名 stem（宠物内唯一，用于定位文件）
  display_name TEXT NOT NULL,      -- 显示名（**用户可随时编辑**，不因导入/确认而锁定）
  owner_kind  TEXT NOT NULL,       -- 'interactive' | 'state'
  kind        TEXT,                -- 'interactive' → 'click'/'drag'；'state' → NULL
  enabled     INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (pet_id, action)
);

CREATE TABLE action_states (       -- 动作 → 状态（可多选），概率按状态分别设置
  pet_id   TEXT NOT NULL,
  action   TEXT NOT NULL,
  state_id TEXT NOT NULL,
  weight   REAL NOT NULL DEFAULT 1, -- 该动作在"该状态"下的出现概率
  enabled  INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (pet_id, action, state_id)
);
```

- `owner_kind`：要么绑**交互类型**（click/drag，无状态），要么绑**状态池**（`action_states` 多选）。
- **多选**：一个动作可同时归入多个状态（如"打哈欠"同时属空闲/午休）。
- **概率按（动作,状态）对**：`action_states.weight` 是"在该状态下的概率"，不同状态可不同值。
- **动作不持有 `interval_ms`**：间隔属于**状态**（程序级，§3.2）。
- 交互类（click/drag）无状态归属，由交互层即时处理。

> - `action`（key）= 文件名 stem，用于**定位 zip/素材内文件**；`display_name` 是显示名，**用户可随时编辑**（不因导入/确认而锁定）。
> - 文件名语义不可靠（上传视频不一定规范命名），故导入时**由用户命名/确认显示名**，并配置归属。

## 6. 导入方式（三种）

| # | 方式 | 输入 | 场景 | 说明 |
|---|---|---|---|---|
| A | 绿幕 mp4 导入（核心）| 绿幕 mp4 | 自己做/扩充动作 | 上传 → 选宠物（或**新建**）→ **手动命名动作 + 配归属** → **异步转换** → 注册为该宠动作 |
| B | 单动作追加 | 单个 webm | 已有宠扩充 | 直接注册（命名 + 配归属）|
| C | ZIP 包导入（传播）| webm + 配置 | 用户间传播 / 市场 | 解压校验 → 注册为（新/既有）宠物；**含待机动画**；有配置 → 确认导入，无 → 手动配置 |

- **新建宠物（从视频）**：批量上传 mp4 → 逐段**命名 + 配置归属**（交互/多状态概率）→ 选**待机动作作基准** → 异步批量转换 → 注册新宠物。
- **导入时给宠物命名**（`display_name`）；**全身照自动从待机动画取一帧**（见 §7），用户不传不改。
- **动作名由用户命名**（文件名不可靠）；系统用它定位 zip/素材内的 webm。
- **A 转换作业异步**：`queued/running/done/error` + 进度 + **只报成功/失败数量**（细节进日志）；失败**直接忽略、不重试**。

## 7. 全身照（宠物级，自动生成）

- **来源**：从该宠物**待机动画**（体型基准动作）里**提取一帧**作为全身照（`full_body_image`，PNG），存宠物级。
- **用户不单独上传、不支持修改**；要改就改待机动画（改完重新取帧）。
- 控制台**总览展示**；**远期**作为 AI 生成绿幕视频的**关键输入**（全身照 + 动作提示词 → 出 mp4）。
- 本阶段只自动取帧 + 展示，不实现 AI 生成。

## 8. 对外的能力 API（供外部 Agent / 程序）

**独立前缀 `/agent/*`**（对外契约，与内部 `/api/*` 区分，避免外部脚本触达管理端）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/agent/state` | **只读**当前状态（当前宠物、`current_state`、动作、位置、朝向、缩放、可见性）|
| POST | `/agent/play` | `{"action":"…"}` 播放动作（能力，最高优先、不改状态）|
| POST | `/agent/say` | `{"text":"…","duration_ms":…}` 说话气泡 |
| POST | `/agent/move` | `{"x":0.5,"y":0.5}` 移动到归一化位置 |

- **最高优先级、一次性/可替换、不改变状态**。
- **不在此暴露**：状态切换（`set_state`，内部维护）、管理端（`pets/settings/system/import`，走 `/api/*`）。
- 前端「试播一下」按钮走控制台内部 `/api/pet/play`。

## 9. 与现有模块的映射

| 现有 | 到新模型 |
|---|---|
| `素材集` 注册表（pets）| 即**宠物**，去「素材集」叫法；导入时命名 |
| `pet_actions.trigger`（click/drag/idle/turn/move/idle_act）| 拆为 `owner_kind`（interactive/state）+ `kind`(click/drag)，状态归属用 `action_states`（**多状态、按状态各自概率**）|
| 行为引擎 `Behavior` / `pick_next`（扁平占比）| **独立状态机引擎**（纯函数出 current_state）+ 行为层状态池加权随机 |
| `idle_ratio / turn_ratio / act_ratio` | 收敛为「状态调度（weight + time_rules，含 enter/exit）」+「状态内动作权重」|
| `pet.set_state`（曾暴露）| **不再对外**；状态由引擎内部维护；只读 `current_state` |
| 能力（say/play/move）| 归入**能力层**，最高优先级、不改状态 |
| `reference_image` | 语义改为**全身照 `full_body_image`** |

## 10. 默认值 / 样品宠物 / 命名

### 10.1 默认状态集合（内置 + 用户可调）
| 状态 | 默认 | 出现频率(weight) | 动作间隔 | 指定时间段 |
|---|---|---|---|---|
| 空闲 idle | 内置 | 70% | 5 ~ 10 s | 无（按频率随机）|
| 活跃 active | 内置 | 30% | 2 ~ 3 s | 无（按频率随机）|
| 午休 lunch | 默认添加 | 0%（仅固定时段）| 5 ~ 8 s | 12:30 – 14:00（可改）|

- 全局 `window_minutes` 默认 **60**（权重随机的窗口粒度）。
- 用户可增删/改名/调参/启停这些状态。

### 10.2 样品宠物（开箱即用）
- 默认用仓库根目录的 **`deskpet-default.zip`** 作为首个样品宠物（导入即注册为当前宠物）。
- 该包需符合 zip 结构（含待机动画 + 动作清单，见 §11）。

### 10.3 命名
- 产品对外名：**DeskPet**（项目英文名）。
- 宠物名：导入时用户命名（`display_name`）；动作名由用户命名。

## 11. ZIP 传播包结构（清单已写实）

```
envelope.zip
├── manifest.yaml   ← 可选清单（动作名 → 归属/概率 + 待机标记 + 宠物默认名）
├── 站立摇晃.webm     ← 动作文件（key = 文件名 stem）
├── 打滚.webm
├── 挥手打招呼.webm
└── …
```

**`manifest.yaml`（可选；省略则导入后由用户手动配置）**
```yaml
pet:
  name: 蓝发女仆          # 导入时的默认名（用户可改）
idle: 站立摇晃             # 待机动作(key)：体型基准 + 全身照来源（**必填**，找不到则提示包不合规）
actions:
  - file: 站立摇晃          # 对应 zip 内文件名 stem
    display_name: 站立摇晃   # 显示名（导入后用户仍可随时改）
    owner: state            # state | click | drag
    states:                 # owner=state 时使用；可多状态、按状态给权重
      - { state: idle, weight: 0.6 }
      - { state: active, weight: 0.8 }
  - file: 打滚
    display_name: 打滚
    owner: state
    states:
      - { state: idle, weight: 0.4 }
  - file: 挥手打招呼
    display_name: 挥手打招呼
    owner: click            # owner=click/drag → 交互类，无 states
```

- 清单格式 **YAML**（与项目配置一致，serde_yaml/serde_yml 解析）。
- `action`（key）与 zip 内文件名 stem 一一对应，实现定位。
- **必须含一个"待机"动作**（体型基准 + 全身照来源）。
- 默认值：未在清单声明归属的动作 → 归入 `idle` 状态池、`weight=1`、启用。
- **导入确认流程**：有 manifest → **预览/可编辑 → 确认导入**；无 → 导入后手动配置。
