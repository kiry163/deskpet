# deskpet 需求规格（发展设计）

> 状态：**草案**（2025）。本文档梳理产品发展方向，作为实现的分期依据；
> 与《技术选型、现状与路线图》配套（路线图负责分期，本文负责需求细节）。

| 需求域 | 核心目标 | 阶段 |

## 1. 素材与软件分离

### 1.1 现状与差距

- 现状：`build.rs` 把 `assets/videos/*.webm` 打包为 `assets.pak`，
  `assets.rs` 用 `include_bytes!` 内嵌进 exe（约 36MB 含素材）；
  分类逻辑（`state.rs build_categories`）已支持 manifest / 子目录 / 关键词兜底三种方式。
- 差距：素材编译进二进制，无法独立更新/替换；exe 体积包含素材。

### 1.2 目标

- 素材**不内嵌** exe；启动时从外部目录加载（目录 + manifest）；
- 配置文件指定素材路径与角色；缺省为 exe 旁 `assets/`；
- 移除/保留内嵌素材作为兜底：**默认外部加载**，无素材时提示放置（exe 可进一步瘦身）。

### 1.3 目录约定（草案）

```
deskpet/                      # 分发根（zip 解压后）
├── deskpet.exe               # 软件本体（不含素材）
└── assets/                   # 素材根（配置可改路径）
    └── <角色名>/             # 一个角色一个子目录（后期可多角色切换）
        ├── manifest.json     # 角色元数据 + 动作分类（§1.4）
        └── videos/           # 动作 webm；可用动作语义子目录（idle/turn/move/click/drag/random）
```

### 1.4 素材 manifest 规范（草案）

```json
{
  "id": "shenshen",
  "display_name": "深神",
  "canvas": { "w": 640, "h": 360 },
  "actions": {
    "idle":  ["待机呼吸休闲"],
    "turn":  ["东张西望"],
    "moves": ["螃蟹走路", "原地漂浮踏步", "原地左转奔跑"],
    "clicks":["点击回应 - 开心跃动", "点击回应 - 害羞惊讶"],
    "drag":  "被鼠标拖拽悬空反馈",
    "acts":  ["玩魔方", "吐泡泡"]
  }
}
```

- `actions` 字段与现有 `build_categories` 的 manifest 解析一致（缺省时回退到
  子目录分类 / 关键词兜底）；
- `canvas` 缺省 640×360；动作文件格式 VP9+alpha webm（与内置一致）；
- 多角色：`assets/` 下多个角色目录，配置 `character` 切换（P5 界面化）。

### 1.5 配置扩展（config.json）

```json
{
  "assets_dir": "C:/path/to/assets",   // 素材根；缺省 = exe 旁 assets/
  "character": "shenshen",             // 角色子目录；缺省取 assets/ 下唯一角色
  "rx": 0.83, "ry": 0.62,
  "facing_right": true,
  "scale": 0.72,
  "always_on_top": true,
  "no_move": false,
  "behavior": { /* 见 §5 */ }
}
```

## 2. 打包分发（zip）

```
deskpet-v0.1.0-windows-x64.zip
├── deskpet.exe
├── assets/                    # 内置素材（§1.3）
├── README.txt                 # 使用说明 + 素材来源声明（MIT 致谢）
└── LICENSE
```

- 素材与软件**同包分发但相互独立**（exe 不内嵌素材，可单独替换素材包）；
- 后续可支持：素材包独立分发/更新（替换 assets/ 即可）、多平台包命名
  （`deskpet-v<版本>-<平台>-<arch>.zip`）。

## 3. 自定义素材

- 用户提供 `assets/<角色名>/`（videos + manifest.json），配置 `character` 切换；
- 校验与兜底（复用现有逻辑）：
  - 缺 `idle` → 首个动画兜底；
  - 缺 `turn/moves/clicks/drag` → 关键词识别兜底；
  - 分类缺失的动作语义不进入对应池；
- 素材合法性：webm 解析失败跳过并告警；全部失败则提示素材无效；
- P5 配置界面提供导入向导（复制/校验/预览）。

## 4. Agent 控制（MCP / CLI / Hooks）

### 4.1 通道

| 通道 | 触发 | 形式 |
|---|---|---|
| **CLI** | 任意脚本/终端 | `deskpet say "…"` / `deskpet play <action>` / `deskpet move <x,y>` … |
| **MCP server** | agent 主动调用 | stdio，暴露 `pet.say / pet.play / pet.move / pet.set_state / pet.get_state` |
| **Hooks** | agent 生命周期事件（codex/claude/opencode）| 配置脚本 → JSON 指令 → 本地端点 |

### 4.2 本地端点

- Windows 命名管道 / macOS Unix socket；单实例进程内持有；
- **单实例配合**：重复启动或控制命令到达时，唤醒已运行实例并执行指令（与 P2 单实例锁联动）；
- 协议：JSON 行（`{op, args?, seq}`），`seq` 用于请求/响应关联。

### 4.3 指令协议（草案）

| op | args | 说明 |
|---|---|---|
| `say` | `{text, duration_ms?}` | 桌宠说话：气泡 + 指定时长（口型动作素材可选）|
| `play` | `{action}` | 播放指定动作（动作名或语义 idle/turn/move/act）|
| `move` | `{x, y}`（归一化 0..1）| 移动到工作区指定位置 |
| `set_state` | `{no_move?, always_on_top?, scale?, visible?, facing_right?}` | 设置状态 |
| `get_state` | — | 返回当前状态（动作/位置/朝向/缩放/可见性）|
| `quit` | — | 退出 |

响应：`{ok, seq, data?}`；`get_state` 返回状态对象。事件（可选，P4 后期）：
`{event: "action_started"|"action_ended", action, seq?}`。

### 4.4 桌宠侧行为

- 外部指令以**高优先级**插入动画链状态机（`pet.rs` 增加指令队列）；
- `say` 的气泡为平台层绘制（Win32 GDI / AppKit 文本），不依赖素材；
- `play` 的动作名解析顺序：精确名 → 语义名 → 最近匹配。

## 5. 行为策略配置

### 5.1 现状（硬编码）

- 动画链概率：`P_IDLE=0.30 / P_TURN=0.40 / P_ACTS=0.80`
  （即 idle 30% / turn 10% / act 40% / move 20%；`no_move` 时 move 并入 act）；
- 移动参数：`MOVE_MIN_PX=60 / MOVE_MAX_PX=240 / MOVE_MARGIN=20 /
  MOVE_LEAD_SEC=2 / MOVE_TAIL_SEC=2`；
- 缩放档位、拖拽阈值、角落边距均为常量。

### 5.2 需求

- `behavior` 配置块（§1.5）：

```json
{
  "behavior": {
    "mode": "balanced",                  // calm / balanced / lively（预设，可被 weights 覆盖）
    "weights": { "idle": 0.3, "turn": 0.1, "act": 0.4, "move": 0.2 },
    "move": { "min_px": 60, "max_px": 240, "margin": 20 },
    "scale_steps": [0.5, 0.72, 0.85, 1.0]
  }
}
```

- 行为模式预设（缺省，用户可自定义权重覆盖）：
  - `calm`：低 move/act 权重（安静陪伴）；
  - `balanced`：现默认分布；
  - `lively`：高 act/move 权重（活泼）；
- 实现：`state::pick_next` 等改为接收策略参数（默认值 = 现常量），
  `config.rs` 扩展结构 + 迁移默认值。

## 6. 配置界面（P5，后期）

- 管理：角色/素材（选择、导入、预览、校验）、行为策略、外观（缩放/置顶）、位置；
- 承载：独立窗口（原生：Win32 对话框 / AppKit 窗口；不引入 Web 前端）；
- 界面修改的配置写入同一 `config.json`，桌宠侧热生效（无需重启）。

## 7. AI 生成素材（P5，远期）

复用 [dsh-pet 的 MIT 生成管线](https://github.com/PC2005-cloud/dsh-pet/blob/master/DESIGN.md)：

```
AI 提示词（角色 + 动作分解）
  → 视频生成 API（绿幕 16:9）
  → HSV 抠像（绿相 70~170° 且 饱和度/明度 ≥0.15 → 透明）
  → 归一化（统一画布、居中、脚底锚点）
  → 转码 VP9+alpha webm → 写入素材包（videos + manifest.json）
```

- 配置界面内：描述角色 → 选动作模板（内置 51 段动作提示词为模板库起点）→
  逐动作生成/预览 → 打包为新角色素材包；
- 涉及外部 API 成本与条款，P5 阶段再定选型。
