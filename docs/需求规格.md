# deskpet 需求规格（V3 草案）

> 状态：**V3 草案**（2025-12 修订）。方向：**桌宠运行时 + 素材工作台**。
> 语义层**抹除「素材/素材集」概念**，统一为**宠物（pet）+ 动作（action）**；
> 自主动作改为**阶段（状态）驱动调度**（替换扁平「闲时占比」）；引入**三种导入方式**、
> **异步转换作业**、**宠物全身照**。
> 本文记录需求与分期；**行为状态机的详细设计见《行为状态机设计》**；技术选型见《可行性分析与技术选型》。
> V2 中「素材集」相关表述已废弃、不再维护。

---

## 1. 方向总览

- **语义**：只用「宠物 / 动作」。每只宠物 = 一套动作；动作只属于一只宠物；桌面始终只显示一只当前宠物。
- **自主动作**：宠物**不是一直随机播放**，而是处于某个**状态（idle/active/…）**下，播放该状态用户配置的动作池；
  状态切换按**时间轮 + 加权随机**调度（程序级），未来支持固定时段规则（如午休）。
- **配置分层**：单一 YAML（仅系统级引导）+ SQLite（程序级与宠物级）；状态节奏为程序级，动作归属为宠物级。
- **导入**：绿幕 mp4 导入（异步转换）/ 单个 webm 追加 / ZIP 包传播；**导入前必须选定宠物**。
- **工作台**：控制台承担「管理桌宠 + 制作宠物资材」双重角色；每只宠物带全身照（供未来 AI 生图输入）。

## 2. 配置架构

### 2.1 分层原则

| 层 | 载体 | 内容 | 特点 |
|---|---|---|---|
| 系统级 | `deskpet.yaml`（唯一 YAML）| `database_path` / `assets_dir` / `console_port` / `log_level` | 启动前必须已知；可手改 |
| 程序级 | SQLite `app_settings` | 当前宠物、位置/缩放/置顶/朝向/不移动、**状态调度**（idle/active 权重、时间窗=1h）、动作默认间隔、移动参数、**转换作业默认参数**、任务并发 | 控制台可编辑、热生效；全局节奏，不随宠物变 |
| 宠物级 | SQLite `pets` + `pet_actions` | 宠物显示名、**全身照**、动作归属（交互 or 状态池）、状态池内每动作 weight/enabled | 按宠物隔离 |

> 规则不变：YAML 只放引导级；开源自启以系统机制（注册表 / LaunchAgent）为事实来源，不入 YAML。

### 2.2 首次运行流程

1. 无 `deskpet.yaml` → 生成默认（默认 db 路径 = 配置目录下 `deskpet.db`）；
2. 打开 db → 不存在则自动建库（schema 版本化迁移）；
3. 无当前宠物 → 控制台引导：导入一个宠物（ZIP 传播包 / 逐动作从 mp4 创建）。

## 3. SQLite 数据模型（草案）

```sql
CREATE TABLE pets (                -- 宠物注册表（原「素材集」，去名）
  id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,          -- 导入时命名；展示一律用此名称
  full_body_image TEXT,            -- 全身照：**自动从待机动画取一帧**（用户不传不改）
  idle_action TEXT,                -- 体型基准动作名（待机），用于归一化基准 + 全身照取帧
  source TEXT NOT NULL,            -- 来源（zip 文件名 / 逐个动作创建 / 内置）
  imported_at INTEGER NOT NULL,
  builtin INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE pet_actions (         -- 动作注册表
  pet_id      TEXT NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  action      TEXT NOT NULL,           -- 动作 key = webm 文件名 stem（宠物内唯一，定位文件）
  display_name TEXT NOT NULL,          -- 显示名（用户**可随时编辑**，不因导入/确认锁定）
  owner_kind  TEXT NOT NULL,           -- 'interactive' | 'state'
  kind        TEXT,                    -- interactive → 'click'/'drag'；state → NULL
  enabled     INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (pet_id, action)
);

CREATE TABLE action_states (       -- 动作 → 状态（多选），概率按状态分别设置
  pet_id   TEXT NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  action   TEXT NOT NULL,
  state_id TEXT NOT NULL,
  weight   REAL NOT NULL DEFAULT 1, -- 该动作在"该状态"下的出现概率
  enabled  INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (pet_id, action, state_id)
);

CREATE TABLE app_settings (        -- 程序级配置（value 存 JSON；含状态调度/转换默认/行为参数）
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE import_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pet_id TEXT, file_name TEXT, result TEXT, detail TEXT, created_at INTEGER
);

CREATE TABLE convert_jobs (        -- 异步转换作业（mp4 → webm）
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  pet_id TEXT NOT NULL,
  src_path TEXT NOT NULL,          -- 用户上传/指定的 mp4
  status TEXT NOT NULL,            -- queued / running / done / error
  progress REAL NOT NULL DEFAULT 0,
  error TEXT,
  created_at INTEGER NOT NULL,
  finished_at INTEGER
);

-- 预留：chat_log（后续聊天）
```

- **动作清单以文件系统为准**：扫描宠物素材目录 `*.webm`；`pet_actions` + `action_states` 为其覆盖配置
  （未登记动画默认归入 `idle` 状态池、`enabled`、`weight=1`）。
- **默认归属**：导入后全部动作默认归入 `idle` 状态池并启用（保证宠物会动）；交互类动作由用户在管理端指定。

## 4. 宠物管理

- **新建宠物（从视频，向导）**：批量上传 mp4 → 逐段**命名动作 + 配归属**（交互/多状态概率）→
  选**待机动作做体型基准** → 异步批量转换 → 注册新宠物；**全身照自动从待机动画取一帧**。
- **导入**（三种）：
  - **绿幕 mp4**：上传 mp4 → **命名 + 配归属** → 提交**异步转换作业** → 出 webm → 注册为该宠动作；
  - **单个 webm**：直接注册为一个动作（命名 + 配归属，无需转换）；
  - **ZIP 包**（传播）：递归扫描 `*.webm` + **可选 `manifest.yaml`**（动作名→归属/概率 + 待机标记 + 宠物默认名，
    格式写实见《行为状态机设计》§11）→ 新注册或并入既有宠物。**必含待机动画**；
    **有 manifest → 预览/可编辑 → 确认导入；无 → 导入后自行配置**。
- **动作归属（多选，按状态给概率）**：一个动作可归入多个状态，每个状态有自己的出现概率；
  交互类（click/drag）不绑定状态。
- **动作显示名**：`display_name` 与 `action`(key=文件名) 解耦，**用户可随时编辑**（不改文件定位）。
- **切换**：选择当前宠物 → 热加载；桌面始终单只；程序级外观/位置全局，切换不重置。
- **删除**：默认仅移除注册、保留文件（可再导入）；提供「连同文件删除」二次确认。
- **预览**：服务端解码出帧图（复用 vpx 解码器，精确复刻桌宠渲染）；动作卡片直接内嵌播放 webm。
- **全身照**：**自动从待机动画取一帧**；用户不上传、不改（改待机动画即改）。
- **转换失败**：只报**成功/失败数量**，细节进日志；失败**直接忽略、不重试**。

## 5. 行为引擎（状态机引擎 + 行为层）

> **详细设计见《行为状态机设计》。** 摘要把「决策」与「执行」分离：
- **状态机引擎（决策，独立纯函数）**：`时钟 × 状态集合配置 → current_state`；**内部维护**，不对外设置状态。
  - 状态集合**程序级、用户可编辑**（内置 idle/active + 默认预置 lunch 午休）；每状态 `weight`（随机，0=不随机）+ `time_rules[]`
    （固定时段，命中强制）+ `interval_ms`（**动作间隔，状态级**）；进入/结束时机可配（默认准点）。默认值见《行为状态机设计》§10.1。
  - 多规则同时段命中 / 自由时段 → **一律按 weight 加权随机，无优先级**；窗口粒度 `window_minutes`（默认 60）。
- **行为层（执行）**：读 `current_state` → 在状态池内**按动作在该状态的权重**加权随机播放 → 按**当前状态的间隔**停顿 → 循环。
- **交互优先**：`click`/`drag` 即时回应；**不改变状态**。
- **能力层（外部 Agent，最高优先级）**：`play / say / move` 等，一次性/可替换，**不改变状态**；
  只读 `current_state` 供展示/Agent，**不对外暴露状态切换**。

| 现有 | 新模型 |
|---|---|
| `click / drag` | 保留为**交互触发**（仅这两类），不绑定状态 |
| `idle / turns / moves / acts` | **全部并入状态池**，状态归属用 `action_states`（**多状态、按状态各自概率**）|
| `idle_ratio / turn_ratio / act_ratio` | 收敛为「状态调度（weight + time_rules + interval）」+「（动作,状态）权重」|

## 6. 控制台界面

1. **总览**：当前宠物（**全身照** / 名称 / 缩略预览 / 状态：当前动作、**当前状态**、位置、朝向、缩放、可见性）
   + 快捷指令（**play 试播 / move / quit**）+ 程序级配置摘要 + 系统信息。
   > 「跟宠物说话」(say) 主要供**外部 Agent/程序**调用，**不放在控制台前端**（仅作 API）。
2. **宠物管理**：
   - 列表（卡片：全身照 / 名称 / 动作数 / 导入时间 / 当前标记；**网格 ▦ / 列表 ☰** 切换；切换 / 删除；**＋导入宠物**；无宠物则显示"还没有宠物"）。
   - 宠物详情（进入即动作管理）：动作清单（**内嵌播放预览**、网格/列表切换）；每个动作：**命名**、触发方式（点击/拖拽/按时段）、
     **归属状态（多选）** + **按状态各自的出现概率**、启用；**＋导入动作**（webm 直导 / mp4 转换）；**✎编辑**（名称）；**全身照自动生成**（只读展示）。
   - **新建宠物（从视频向导）**：批量上传 mp4 → 逐段命名 + 配归属 → 选**待机动作作基准** → 异步批量转换 → 注册。
3. **状态配置（程序级）**：状态集合（空闲/活跃/午休 + 自定义）：出现频率、指定时间段、**动作间隔**、进入/结束方式、启停；＋新增状态。
4. **设置**：程序级行为（移动参数 / 缩放档位）+ 外观 + **视频转换默认参数** + 系统级（YAML）。
   > 状态调度（状态集合、window_minutes、interval）在「状态配置」页配置。

## 7. API（两组前缀：对外 Agent 契约 + 控制台内部）

**一组 HTTP 服务、两组前缀**，避免外部脚本误触管理端、对外契约更干净。

### 7.1 外部 Agent / 程序 API（前缀 `/agent/*`，对外最小稳定面）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/agent/state` | **只读**当前状态（当前宠物、`current_state`、动作、位置、朝向、缩放、可见性）|
| POST | `/agent/play` | `{"action":"…"}` 播放动作（能力，最高优先、不改状态）|
| POST | `/agent/say` | `{"text":"…","duration_ms":…}` 说话气泡 |
| POST | `/agent/move` | `{"x":0.5,"y":0.5}` 移动到归一化位置 |

不在此暴露状态切换（`set_state`，内部）与管理端（/api/*）。

### 7.2 控制台内部 API（前缀 `/api/*`，前端 + 管理 + 素材工作台）

保持现有 `state / config / pet.say / pet.play / pet.move / import / quit` 兼容；
**`pet.set_state` 不再对外暴露**（状态由引擎内部维护）。新增：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pets` | 宠物列表（含当前标记）|
| GET | `/api/pets/{id}/current-state` | **只读**当前状态（前端展示 / 试播）|
| POST | `/api/pets/{id}/switch` | 切换当前宠物（热生效）|
| DELETE | `/api/pets/{id}` | 删除宠物（默认保留文件）|
| GET / PUT | `/api/pets/{id}/actions` | 动作归属与权重配置（热生效）|
| GET | `/api/pets/{id}/preview?action=*&frame=*` | 动作预览帧（PNG）|
| GET / PUT | `/api/pets/{id}/full-body` | 全身照管理 |
| POST | `/api/pets/{id}/import/video` | 提交 mp4 绿幕转换作业（异步）|
| GET | `/api/pets/{id}/jobs` | 该宠物转换作业列表与进度 |
| POST | `/api/pets/{id}/import/webm` | 导入单个 webm 作为动作 |
| POST | `/api/import` | ZIP 包导入（传播/新宠物，可含命名 + 可选 config）|
| GET / PATCH | `/api/settings` | 程序级配置（**含状态集合与调度**：weight/time_rules/enter/exit/window_minutes）|
| GET | `/api/system` | 系统级配置（YAML）+ 版本 |

## 9. 关键决策记录

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 语义 | **抹除「素材/素材集」**，统一「宠物 + 动作」；动作只属于一只宠物；交互仅 `click`/`drag` 两类；导入时命名 |
| 2 | 自主调度 | **独立状态机引擎**（决策）+ 行为层（执行）：状态集合（可自定义）+ 每状态 `time_rules`（进入/结束时机可配，默认准点）、`weight`（随机，0=不随机）、`interval_ms`（**动作间隔，状态级**）同级可调；状态池内加权随机 |
| 3 | 配置分层 | 程序级 = 状态集合调度/转换默认（**含各状态动作间隔**）；宠物级 = 动作归属 / **（动作,状态）概率** / 命名；**不做宠物级覆盖**；YAML 仅引导 |
| 4 | 引擎职责 | 状态机**纯函数出 current_state**；**交互/能力不改变状态**；**状态切换不对外暴露**（仅只读 current_state）|
| 5 | 导入 | 绿幕 mp4（**手动命名+配归属**，异步转换）/ 单个 webm / ZIP 包传播（**必含待机动画**；有 config 确认导入，无则手动配置）；**新建宠物=从视频向导** |
| 6 | 转换作业 | **异步任务 + 进度反馈**；**只报成功/失败数量**，细节进日志；失败**忽略、不重试** |
| 7 | 全身照 | **自动从待机动画取一帧**（用户不上传不改）；控制页展示；**远期**作 AI 生成绿幕视频的**关键输入** |
| 8 | 能力 API | `play / say / move` 供**外部 Agent** 调用，**最高优先级、不改状态**；「跟宠物说话」**不放控制台前端**（仅 API）|
| 9 | 画布 | **不强解耦**：转换与渲染强制 640×360 / PAD=30（作为当前约束）|
| 10 | API 前缀 | **对外 Agent `/agent/*`（能力 + 只读 state）与控制台内部 `/api/*`（管理 + 工作台）分离**；`set_state` 不对外 |
| 11 | 动作↔状态 | **一个动作可归入多个状态**（`action_states` 多选），**概率按（动作,状态）分别设置** |
| 12 | 默认状态 | 内置空闲(70%)/活跃(30%) + 默认预置**午休**；窗口 60 分钟；间隔 空闲5~10s/活跃2~3s/午休5~8s |
| 13 | 样品宠物 | 默认用仓库根 `deskpet-default.zip` 作首个样品宠物 |
| 14 | 命名 | 产品对外名 **DeskPet**；宠物/动作名由用户命名 |
| 15 | 传播包清单 | **写实为 `manifest.yaml`**（动作名→归属/概率 + 待机标记 + 宠物默认名），见《行为状态机设计》§11 |
| 16 | 动作显示名 | `display_name` 与 `action`(key=文件名) 解耦，**用户可随时编辑**，不因导入/确认锁定 |
| 17 | 数据库路径 / 桌宠形态（单只）/ 预览（服务端出帧）/ 删除（默认留文件）/ 旧版不迁移 | 沿用 V2 决策 |
